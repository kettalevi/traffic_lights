# traffic_lights

PHP + MySQL + JavaScript (Bootstrap 5) controller for **four roads**, each with Red / Orange / Green.
Every road gets **2 minutes of green by default**. The same live state drives physical lights *or* ordinary
screens, so locations without lights get identical guidance.

## How it works

```
Admin (PHP/MySQL) ──► signal_state row ◄── /api/state.php ◄── screens (display.php)
                                                      ▲
                                                      └──── hardware light controllers
```

* Cycle per road: **Green → Orange → all-red gap → next road's Green**, round-robin over enabled roads.
  Defaults: green 120 s, orange 4 s, all-red 2 s (all configurable).
* `/api/state.php` is the single source of truth. Each call advances the state machine inside a DB
  transaction, so every screen and light agrees, with no background process or cron needed.
* Screens use the server's clock (not their own), show the colour **and** a text cue (GO / PREPARE TO STOP / STOP)
  plus a countdown, and **fail safe to flashing orange** with a banner if the link to the server is lost for 10 s.
* If nothing polls for over 60 s the cycle restarts cleanly from an all-red gap rather than replaying old time.

## Setup

Requirements: PHP 8.1+ with `pdo_mysql`, MySQL/MariaDB.

```sh
mysql -e "CREATE DATABASE traffic_lights CHARACTER SET utf8mb4; CREATE USER 'traffic'@'localhost' IDENTIFIED BY 'secret'; GRANT ALL ON traffic_lights.* TO 'traffic'@'localhost';"
cat > config.local.php <<'PHP'
<?php return ['db_pass' => 'secret', 'timezone' => 'Africa/Nairobi'];   // timezone is used by time-of-day rules
PHP
php setup.php --user=admin --pass='choose-a-strong-one'   # creates tables, 4 roads, first admin
php -S 0.0.0.0:8000 -t public                             # or point Apache/nginx at public/
```

(`schema.sql` is the same schema for importing via phpMyAdmin; it is generated by `php setup.php --dump-sql`.
Settings can also come from env vars: `DB_HOST DB_NAME DB_USER DB_PASS APP_TIMEZONE`.)

Only `public/` should be web-accessible; `src/`, `config*.php` and `setup.php` stay outside the web root.

## Pages

| URL | Purpose |
|---|---|
| `/display.php` | All four roads on one screen (2×2) |
| `/display.php?road=2&kiosk=1` | One road, full screen, no controls or cursor: mount a screen facing that road |
| `/api/state.php` | JSON snapshot (see below) |
| `/admin/` | Administration (login required) |

Tip for screens: open the kiosk URL in Chromium with `--kiosk`; it keeps the screen awake.
For fully offline screens, put `bootstrap.min.css` and `bootstrap.bundle.min.js` (5.3.x) in
`public/assets/vendor/` and they are used instead of the CDN. (The signal display itself needs no Bootstrap.)

## Admin features

* **Override modes**: automatic, flashing orange, all red, or hold one road on green. Resuming automatic goes through an all-red gap.
* **Green time per road**: type a value or use **− / +** buttons (step size configurable), plus all-roads +/− and reset to default.
  Always kept within the configured minimum/maximum. Changes apply from that road's next green.
* **Rules**: time-of-day adjustments that *increase or decrease* green time, for one road or all, on chosen weekdays,
  including overnight windows (22:00–06:00). Matching rules add together, then are clamped to min/max. Rules can be disabled without deleting.
* Take a road out of the cycle ("In cycle" checkbox), global settings, admin accounts, password change, and an audit log.

## JSON for hardware controllers

`GET /api/state.php`

```json
{ "now_ms": 1791564027540, "mode": "auto",
  "phase": { "road": 1, "type": "green", "started_ms": 1791564026526, "ends_ms": 1791564146526 },
  "roads": [ { "id": 1, "name": "Road 1", "light": "green", "changes_at_ms": 1791564146526, "green_at_ms": null } ] }
```

`light` is `green | orange | red | flash_orange | off`. A relay/GPIO controller just polls once a second and
drives the lamps; treat a failed/stale response as flashing orange, as the screens do.

## Tests

`php tests/engine_test.php` runs the timing, rules, override and failure-handling checks against in-memory SQLite (no MySQL needed).

## Safety note

This is software guidance. Before using it to control real road users, add independent conflict-monitoring
hardware (a conflict monitor / malfunction management unit), as required by your local traffic authority.
